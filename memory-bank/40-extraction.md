# Распознавание и извлечение полей

## Почему OCR запускается много раз

Одно изображение прогоняется режимами Tesseract `--psm 3/4/6/11` по
предобработанной картинке плюс один раз по оригиналу. Значение каждого поля
выбирается голосованием в `extract.py::_vote`.

Причина: на фото с телефона одиночный прогон терял цифру в ИНН
(`32410214348` вместо `324103214348`) и превращал «Бурцева» в «Буре».
Предобработка (серый → увеличение ×2 → автоконтраст → нерезкая маска) плюс
голосование это устраняют. **Не упрощай до одного прогона.**

У PDF сначала пробуется текстовый слой через `pdftotext`; OCR включается, только
если текста меньше 400 символов (значит внутри скан).

## Три стратегии выбора значения

1. **Контрольная сумма** (ИНН, СНИЛС) — самый надёжный сигнал. Ошибка OCR почти
   всегда рушит контрольный разряд, поэтому валидное значение побеждает частоту.
2. **Эвристика качества** (адрес) — `_address_score`: без мусорных слов,
   начинается индексом, кончается цифрой, короче — лучше.
3. **Частота** — для остальных полей.

## Особенности парсинга

- Дата документа ищется **только в шапке** (до слова «УСТАНОВИЛ»), иначе
  подхватывается дата судебного заседания из резолютивной части.
- ФИО в документе стоит в родительном падеже; `morph.py` приводит к
  именительному. Отчества — по таблице окончаний, остальное — `pymorphy3`.
- Tesseract искажает окончания и путает латиницу с кириллицей: «ИНН» → «ИНИ»,
  «признании» → «призиации», `A41` → `А41`. Поэтому обрезки идут по корням слов,
  а номер дела нормализуется в `validators.normalize_case_number`.
- ИНН отсутствует у части должников — тогда в карточку пишется номер дела
  (`DebtorCard.inn_or_case`).

## Эталонные значения для регрессии

После правок парсера прогони три образца и сверь. Расхождение — регрессия.

| `opredelenie_2.jpg` | Соколова Мария Ивановна | А41-48291/2026 | 03.09.2026 | 772881234560 |

образце 2 **намеренно не проходит** контрольную сумму — это не баг. Валидный
вымышленный ИНН для новых тестов: `772881234508`.
