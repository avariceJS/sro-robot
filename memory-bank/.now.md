# Bulk document processing — implemented and verified, 2026-10-16

## Current stage: court-document quality

Quality changes are implemented on `develop` after the bulk-stage checkpoint;
see `../docs/quality-benchmark-2026-10-16/README.md` and its frozen synthetic
manifests/results. The OCR path now checks PDF text by page, OCRs blank or
fragmentary pages in bounded groups of at most four, and does not rasterize
ordinary searchable PDFs. Empty page separators skip Tesseract. This fixes a
reproduced searchable-cover/image-only-act omission and bounds memory for long
scans. Photo uploads retain the previous preprocessing pipeline.

Role-bound INN parsing preserves one checksum-valid candidate as a warning-only
manual suggestion when other OCR variants have damaged tokens. Distinct valid
INNs and multiple valid values inside one role section remain withheld. The
automatic-card gate is unchanged: a warning or `role_partial` value cannot
prepare a card. The existing review page renders the value and warning for staff.

Verification on 2026-10-16: 699 Python unittest tests passed with 97 DB-backed
tests skipped because disposable PostgreSQL was not available; all 137 Node
tests passed and compileall succeeded. The 24-file dev synthetic corpus had no
wrong nonempty fields or incorrect card preparations. The separately named and
hashed 24-file heldout corpus matched type/date/case/FIO 24/24, INN 22/24 (two
scan misses), with zero incorrect automatic preparations. This deterministic
synthetic set is not real-office qualification.

On the previously used 50-file regression cohort, exact INN review values rose
from 34/50 to 49/50, with zero wrong nonempty values and one still-missing scan
INN. The local preparation gate admitted 26 candidates; all 26 matched name,
INN, address, case and date. This final parse/gate audit was not a repeated
database-backed upload run. A single serial pair measured 46.46 s before and
49.59 s after on those files (+6.7%). A ten-page sparse scan measured 6.10 s /
921 MiB before and 2.79 s / 504 MiB after bounded rasterization. See benchmark
notes for limitations and the unresolved unanimous wrong date in
`synthetic-091.pdf`.

Real-office accuracy remains unknown because no permissioned representative
corpus was available. Do not interpret synthetic results as office accuracy;
next evidence needed is an approved, locally retained annotated set with an
independent visual gold review. Main/production and SROArbitr remain untouched.

The owner authorized a new bulk-document mission after consolidation. Develop
is the only development branch in the canonical checkout. Publish verified
changes to origin/develop; do not modify main, release, deploy or write SROArbitr.

- Existing 100-file intake, 20-file chunks, durable outbox and fenced OCR remain.

  Browser retry identities survive successful completion/reload; exact ordered
  reselection reuses accepted tasks. This is not cross-user semantic merging.
- Shared dashboard aggregates queued, processing, card-ready, review, failed and
  other work across the complete selection; filtering, pagination, source links
  and polling preserve the selected scope.
- Role-bound extraction rejects applicant/representative fallback, conflicting
  debtor identities, identifiers, dates/cases and uncertain morphology. Empty

- Fenced OCR can prepare an internal person card only with explicit debtor-role
  evidence, full name, valid personal INN, case and act date. It remains
  `preparation_state=prepared`; task approval and all external operations remain
  separate. Conflicting existing INN routes to possible-duplicate review.
- One-action employee correction/approval/card preparation, stale-form snapshot
  checks, row-locked/versioned card edits and attributed append-only internal-card
  revisions are implemented. Reviewed card data cannot be silently overwritten
  by a changed source task. Migration head: `f4b7c2d091a6` (forward-only).
- Authenticated source download validates private storage, size, inode and hash
  through one file descriptor and returns a sandboxed/no-store attachment.

## Known limits and next work

- All 25 scans in the final cohort still require staff review. Across 50 tasks,
  name/case matched 50/50, date 49/50 (one wrong date in review), INN 34/50
  (16 withheld, zero wrong nonempty INNs). Every prepared card field was exact.
- Two same-variant OCR comparisons confirmed that newly visible malformed INN
  tokens now take the fail-closed path; eight other newly missing scans were
  not individually diagnosed. This review-field recall tradeoff is documented
  in `inn-recall-diagnostic-20541c6.md` in the evidence folder. The task-quality
  audit retains `result=findings`; human acceptance is not claimed.
- Retry identity is browser/user/ordered-selection scoped. Other browsers,
  renamed/reordered inputs and other staff can create another task; shared INN
  conflicts are reviewed without automatic merging. Explicit reprocessing and
  cross-source business identity need separate durable contracts.
- The parser is a conservative person-debtor heuristic. Organization/IP cards,
  calibrated confidence and page-aware mixed/long PDFs remain future work.
- Local 12-core/24-GiB results do not qualify VPS capacity or office accuracy.
  Next: an annotated locally retained office corpus, review-burden measurement,
  then production-sized staging qualification and human review before an
  owner-authorized release. Staff steps are in `../docs/BULK_PROCESSING.md`.
