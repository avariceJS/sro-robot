## Observed baseline

Both reached needs_review, zero errors. Database timestamps show 95.624 seconds
from creation to completion for task 4. Task 5 started 96.501 seconds after

Nearly all elapsed time was inside Tesseract. The identity-role parser and
manual review requirement are separate from recognition duration.

## Controlled VPS measurements

Use the existing stored input, capture stdout locally on the VPS without printing
OCR text, and measure `time.monotonic()` around:

```
OMP_THREAD_LIMIT=1 tesseract INPUT stdout -l rus --psm 3
OMP_THREAD_LIMIT=4 tesseract INPUT stdout -l rus --psm 3
```

| Sample | One thread | Four threads | Output equality |
| --- | ---: | ---: | --- |
| 1 | 1.43 s | 5.55 s | Identical SHA256 |
| 2 | 1.91 s | 8.90 s | Identical SHA256 |

The full **unchanged released** `sro_robot.core.ocr.recognize(Path(INPUT))`
with `OMP_THREAD_LIMIT=1` took **9.12 / 12.20 seconds** on the VPS, returning
all five variants. This standalone run did not update tasks or worker settings.
It establishes a strong speed improvement but is not a post-deployment browser
measurement. No concurrency increase or reduction in OCR passes is included.

## Change

Default `OMP_THREAD_LIMIT` to 1 at OCR module import; preserve an explicit operator
override. The setting is inherited by later child processes. Keep preprocessing,
all PSM variants, original-image pass, voting, role checks and approval unchanged.
Reducing image enlargement was rejected because candidate values changed.
A single-pass shortcut was rejected and removed.

Review UI now offers three actions for the observed needs_review person task:
save in place, approve (and advance in a scoped batch), approve and prepare an
internal card. The technical local-validation control and duplicate navigation
buttons were removed. Approved tasks still offer the explicit SRO form preview.
